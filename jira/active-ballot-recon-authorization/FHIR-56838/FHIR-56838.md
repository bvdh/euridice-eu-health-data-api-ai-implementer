# FHIR-56838: Revise authorization page

## Description

1)

The page states that SMART App Launch and SMART Backend Services are authoritative with respect to IUA when they differ, but throughout the page the terminology still refers broadly to IUA. This is confusing, because the page should primarily name and describe the approach that is actually being used.

Proposed Change:

Revise the page so that it consistently refers to SMART where SMART is the actual mechanism being profiled or recommended.

If IUA is only used as a reference framework or background specification, make that explicit

2)

Issue:

The page does not clearly distinguish between preferred and required authorization approaches. As written, it may give the impression that SMART is mandatory, while in practice SMART may be the current preferred option but not the only possible one. This is especially relevant because cross-border trust frameworks may rely on other technologies and agreements.

Proposed Change:

Add wording that clearly separates recommendation from obligation, for example:

“SMART App Launch and SMART Backend Services are the currently preferred authorization approaches in this guide, but they are not the only possible mechanisms. Other approaches MAY be used, provided they satisfy the requirements of this guide and the applicable regulatory and trust framework.”
