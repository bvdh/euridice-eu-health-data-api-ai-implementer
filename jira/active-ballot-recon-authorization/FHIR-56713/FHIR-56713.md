# FHIR-56713: Revise references to IUA

## Description

Issue:

The page states that SMART App Launch and SMART Backend Services are authoritative with respect to IUA when they differ, but throughout the page the terminology still refers broadly to IUA. This is confusing, because the page should primarily name and describe the approach that is actually being used.

Proposed Change:

Revise the page so that it consistently refers to SMART where SMART is the actual mechanism being profiled or recommended.

If IUA is only used as a reference framework or background specification, make that explicit.

 

Please also indicate that SAMRT is not mandatory

## Resolution

- Status: Triaged
- Resolution: Persuasive

This ticket is addressed by the Authorization page changes in [PR #99 — Eu health data api ballot recon authorization](#99 — Eu health data api ballot recon authorization)([https://github.com/euridice-org/eu-health-data-api/pull/99](https://github.com/euridice-org/eu-health-data-api/pull/99)). The page distinguishes SMART App Launch and SMART Backend Services from IHE IUA, describes their respective roles, and selects the applicable profile by environment and flow rather than stating that SMART universally takes precedence over IUA. It clarifies that the environment-specific SMART choice is not an EHDS-wide requirement to use SMART, while retaining IUA as an active option for the stated MyHealth@EU alignment and qualifying national-infrastructure endpoints.
