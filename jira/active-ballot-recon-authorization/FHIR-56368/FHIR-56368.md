# FHIR-56368: Clarify SMART compliance with EU regulation

## Description

The Implementation Guide proposes the use of SMART-on-FHIR for authorization, but it is unclear whether this approach is fully compliant with applicable EU regulations, in particular:

	- eIDAS Regulation (electronic identification and trust services)

	- EU Digital Identity Wallet requirements

	- GDPR-related constraints on authentication and authorization

Add a clarification section describing how the SMART-on-FHIR approach aligns with EU regulatory requirements. This could include:

	- Mapping SMART authentication flows to eIDAS-compliant identity assurance levels

	- Explaining how EU Digital Identity Wallets can be integrated into the SMART authorization flow

## Resolution

- Status: Triaged
- Resolution: Persuasive

The proposed Authorization changes in [PR #99](#99)([https://github.com/euridice-org/eu-health-data-api/pull/99](https://github.com/euridice-org/eu-health-data-api/pull/99)) clarify that, where a selected environment requires eIDAS-recognized electronic identification, the Authorization Server supports that identification for interactive SMART or IUA authorization-code flows, while pre-authorized SMART Backend Services using client credentials are treated separately. The text describes the European Digital Identity Wallet as one possible upstream source of user authentication and keeps Wallet presentations distinct from OAuth grants, access tokens, and API authorization. It does not assign a universal eIDAS assurance level to SMART flows, select a Wallet-to-Authorization-Server profile, or provide a detailed GDPR analysis. These details remain open for separate technical, legal, or workgroup decisions. This resolution text describes work in an open PR and does not assert that it has merged or that Jira has been updated.
