# FHIR-56398: Additional Attributes for Patient Matching

## Description

Additional Attributes for Patient Matching

The support of PDQm as proposed makes sense.  However, the management of the patient identifier(s) would benefit from additional attributes specification often used by existing the national patient identification services: 

	- Some additional attributes should be supported as SHOULD such as sexOrGender, birthLocation, to enable searches aligned with various national policies.

Proposed resolution: 

Extend the Optional Search Parameters with a SHOULD associated to the following: 

	- sexOrGender,

	- birthLocation,

The actual request of this ticket is already fulfilled since both gender and birthplace (in form of an Extension in the EU Core Patient profile) are available as optional attributes on the Patient input parameter for $match. However, an explanation of this behavior will be added to the corresponding chapter for $match for clarification.

### Reinhard Egelkraut — 2026-06-23

Clarification during the EU API call on June 17th 2026 together with the reporter:

The request of this ticket is about $match only and does not affect the patient search requirements.

The input for a $match transaction is a Patient resource, in our case based on the corresponding EU Core profile. According to the PDQm definition for ITI-119 every element of this input is optional a.k.a. SHOULD (see also [https://profiles.ihe.net/ITI/PDQm/StructureDefinition-IHE.PDQm.MatchInputPatient.html](https://profiles.ihe.net/ITI/PDQm/StructureDefinition-IHE.PDQm.MatchInputPatient.html)) which includes gender and derived from the EU Core profile birthplace.

Therefore, the request of this ticket is already fulfilled. However, we should mention this behavior explicitly in the corresponding chapter for $match.

There is a similar request in [FHIR-56684](https://jira.hl7.org/browse/FHIR-56684) to include all the search parameters that are listed in the PDQm ITI-78 transaction as SHALL for the Patient Demographic Supplier Actor (*Access Provider actor in the EU API spec)

the requested gender parameter would be one of them

concerning the requested birthLocation parameter:

	- the information about the birth location exists only as standard Extension "[birthPlace](http://hl7.org/fhir/StructureDefinition/patient-birthPlace)" on the Patient Resource and furthermore is supported by the [EU Base](https://hl7.eu/fhir/base/StructureDefinition-patient-eu.html) and [EU Core](https://hl7.eu/fhir/base/StructureDefinition-patient-eu-core.html) profile for Patient

	- However, it is currently not available as a search parameter (see also the list of [Extension Search Parameters for Patient](https://hl7.org/fhir/extensions/extensions-Patient.html#search))

Given the availability of the other search parameters listed here [https://profiles.ihe.net/ITI/PDQm/ITI-78.html#23784121-search-parameters](https://profiles.ihe.net/ITI/PDQm/ITI-78.html#23784121-search-parameters), is the additional birthPlace parameter still needed?
