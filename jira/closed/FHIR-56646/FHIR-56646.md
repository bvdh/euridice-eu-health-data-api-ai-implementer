# FHIR-56646: Harmonize SMART scope syntax — IG mixes v1 and v2 forms

## Description

authorization.html declares SMART App Launch v2 conventions, but its scope examples use v1 syntax (.read, .search, .create). resource-access.html uses v2 (.rs). The example-patient-summary.html token request uses v1. The IG self-contradicts.

Per [SMART App Launch v2 — Scopes and Launch Context](https://hl7.org/fhir/smart-app-launch/STU2/scopes-and-launch-context.html), valid v2 suffixes are "a subset of the in-order string .cruds". The mappings:

	- .read (v1) → .rs (v2 — read + search)

	- .write (v1) → .cud (v2)

	- .* (v1) → .cruds (v2)

.rs is v2; .read and .search as separate suffixes are v1.

Proposed resolution:

Align everywhere on SMART v2 granular CRUDS:

	- In authorization.html, replace v1 scope examples (system/Patient.read, system/DocumentReference.search) with v2 (system/Patient.rs, system/DocumentReference.rs, system/DocumentReference.c).

	- Rewrite the inline conventions explainer to describe the v2 granular suffixes (.r, .s, .c, .u, .d, and the in-order subset shorthand).

	- Update example-patient-summary.html token request scope strings to v2.

	- Update FSH CapabilityStatements that include scope strings.

Note that servers MAY accept v1 scopes for backward compatibility per SMART v2 provisions, advertising the permission-v1 capability when they do.
