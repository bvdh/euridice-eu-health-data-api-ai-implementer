# FHIR-57228: Editorial: Content vs Exchange Distinction Should Be Prominently Explained

## Description

The Implementation Guide defines exchange patterns (actors, transactions, authorization) but could do a better job explaining the distinction between content creation and exchange, which is critical to the positioning of this IG related to the other HL7 EU IG's as well as the broader EHDS context.

This creates confusion for readers who often conflate content creation and format validation (e.g. FHIR documents that validate against priority category data models) with an exchange transaction or wire format (e.g. publication transaction of a FHIR Document via MHD ITI-105).

These concepts need to be clearly disaggregated in order to define handle multiple deployment patterns:

	- Creation Co-located with Document Access Provider: The system that creates data IS the Document Access Provider. The EHR serves queries directly from its own data. On-demand document generation ([FHIR-56645](https://jira.hl7.org/browse/FHIR-56645)) is a specialization of this pattern where the Document Access Provider generates the document at query-time.

	- Creation Published to Document Access Provider: A separate system creates data and submits it to a Document Access Provider via ITI-105. The Access Provider then serves queries on behalf of the publisher.

Publish transaction =\= the creation of data. Transactions are orthogonal to content creation. 

Proposed Resolution:

In order to allow multiple deployment patterns these concepts need to be clearly stated; recommended in the introduction page or in the background. 

The existing [Regulatory Anchors](https://hl7.eu/fhir/health-data-api/1.0.0-ballot/en/regulatoryAnchors.html#content-vs-exchange) Content vs Exchange page should be promoted to it's own background page or a section in the home page.

## Resolution

- Status: Applied
- Resolution: Persuasive

The homepage Scope prominently distinguishes exchange patterns from the clinical models defined by Content IGs. Document Exchange explains external ITI-105 publication versus grouped/internal publication. Relationship to XDS/FHIR Document Sharing describes on-demand document generation from local resources without inbound publication. Together these distinguish content creation from exchange and cover both co-located creation and external publication. These explanations are already on main at 98a084d3a7172d8d590466327098f72afaa14c3c. No further specification change is needed for this ticket. Implementation proposal: [https://github.com/euridice-org/eu-health-data-api/pull/101](https://github.com/euridice-org/eu-health-data-api/pull/101)
