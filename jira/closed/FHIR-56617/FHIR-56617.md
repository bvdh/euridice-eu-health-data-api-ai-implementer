# FHIR-56617: Revise the guidance on identification practices

## Description

The current text states:

“Patient.Search [ITI-78] should be used when a patient identifier (e.g. National ID) is available and trusted. If an identifier is not available, Patient.$match [ITI-119] should be used to perform a demographics search operation with available demographics.”

This approach is not compatible with cross-border exchange in the European context and other contexts because:

	- Patient discovery based on demographics is generally not allowed; the patient must already be known (no open-ended search)

	- Not all countries use a national patient identifier; instead, identification may rely on a set of agreed identification attributes

 

Suggest to revise the guidance on identification practices when no demographic discovery is allowed.

## Resolution

- Status: Applied
- Resolution: Persuasive
- Resolution Vote: Mattias Colliander / Charles Parisot: 6-0-1
- Vote Date: 2026-08-12

After a discussion on the API call the agreement was to keep the status quo, meaning that patient search is required and $match optional. Providing identifier and/or demographics can be accomplished with patient search (reminder: SHALL support a certain search parameter means that a system has to able to process it and not that is has to be present in every query). It depends on the governance for the identifier and the “set of agreed identification attributes” what to use, which is varying between the member states. Furthermore, some guidance will be added that explains how the patient lookup is initiated in the cross-border use case, what the pre-conditions are (e.g. patient properly identified and identification derived from EUDI Wallet) and what its purpose is (confirmation of the identification).
