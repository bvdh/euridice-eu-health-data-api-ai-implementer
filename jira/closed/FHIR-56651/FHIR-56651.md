# FHIR-56651: Resource search: don't require `patient` for resources that aren't patient-scoped

## Description

The IG requires the patient parameter on all resource-access searches. Some resources implied or referenced here (e.g., Organization, Practitioner, Location) are not patient-scoped and wouldn't naturally accept it. Even if those resources aren't currently supported, the conformance text shouldn't require a parameter that doesn't apply.

Patient parameter should only be required where supported. Some of these resources imply the existence of e.g. Organization/Practitioner, which do not require a patient. Even if those are in fact not supported today, still feels like a worthwhile update for future-proofing. The list also does not seem to be up to date with the Open Issue 9 page, which might be intentional.

Proposed resolution:

Follow IPA STU1's pattern: IPA is exclusively patient-scoped (no Organization or Location resources defined; Practitioner and PractitionerRole are reference-only with no search parameters). When non-patient-scoped resources are introduced (per open-issues.html#issue-9), they should be defined with their own conformance levels — not caught by the patient-required SHALL.

Adjust the SHALL/SHOULD search-parameter conformance so patient is required only on patient-scoped searches. Reconcile with open-issues.html#issue-9 for resources to be added.

Distinct from the IPA STU1 search-parameter alignment ticket (#1, required combinations on patient-scoped resources); this ticket addresses whether patient is the right required parameter for non-patient-centric resources.

Reporter(s): Aaron Mahr, Epic
