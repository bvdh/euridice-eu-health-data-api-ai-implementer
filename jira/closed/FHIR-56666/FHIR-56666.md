# FHIR-56666: Editorial: example Patient Summary page — token label, link target, issue number, DocumentReference category

## Description

Four small fixes to the worked example:

	- Step 2 heading reads "Obtain Authorization Token"; should be "Obtain Access Token" (the request obtains an access token, not the authorization).

	- The "Patient Match" link in step 3 points to a Patient.Search example. Either rename the link to "Patient Search" or retarget it to a $match example (dovetails with the patient-matching disposition).

	- The page references "Issue 12" but [open-issues.html](https://build.fhir.org/ig/euridice-org/eu-health-data-api/en/open-issues.html) lists issues 1, 9, and 12 (or possibly 50). Verify the intended issue number and reconcile with open-issues.md.

	- The example's DocumentReference.category uses an XDS classCode without explanation. Add a one-line comment on the coding choice, or drop category to avoid implying a specific binding.

Reporter(s): Aaron Mahr, Epic; Isaac Vetter, Epic
