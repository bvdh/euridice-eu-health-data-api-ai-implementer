# FHIR-56847: Formilize  DocumentReference  expectations

## Description

Issue:

The documentation specifies requirements such as:

“The DocumentReference SHALL include:

status (required)

type (required - LOINC document type)

subject (required - Patient reference)

content.attachment.contentType (required)

content.attachment.data (required - base64-encoded document content)”

However, these constraints are expressed only in narrative form

Proposed Change:

Define a minimal DocumentReference profile - non derived from the MHD DocRef profile, that includes alao other constraints as category ..1 - capturing these constraints and reference it in the CapabilityStatement, e.g.:

	- Create a StructureDefinition (e.g., EEHRxF Minimal DocumentReference) with the specified cardinalities and bindings

	- Reference this profile in the CapabilityStatement as the required supported profile
