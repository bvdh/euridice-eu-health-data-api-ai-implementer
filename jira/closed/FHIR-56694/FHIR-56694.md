# FHIR-56694: Document Exchange needs extensions to the required search metadata

## Description

The support of MHD as proposed makes sense, however:

	- The document search proposed in the use of the MHD Document Reference resource is too primitive as it only relies on two mandatory parameters: documentType limited to the EHDS Data Category (encoded by a value set of 6 arbitrarily picked LOINC Code) and document contentType (MIME Type).

	- This extended list of search parameters below shall be required to support server-side filtering (shown by *):

 - A subset shall be supported for search query request (server-side filtering).

 - All need to be returned whether they were or not included in a query instance.

 ** 

Proposed resolution :

It is proposed to Update the Search Strategy that is only vaguely described in: [https://hl7.eu/fhir/health-data-api/1.0.0-ballot/en/document-exchange.html#document-search-strategy](https://hl7.eu/fhir/health-data-api/1.0.0-ballot/en/document-exchange.html#document-search-strategy) ** :

The following are generic search metadata (requested and returned) need to be the “quasi comprehensive” set (minus the confidentiality code that is not useful to debate outside the security and privacy strategy):

	- Document Creation Date/Time* ==> Critical to perform incremental queries

	- Period (Start time*-End time)      ==> query by time the care was delivered

	- Last updated*                              ==> Time the document was last updated (incremental queries)

	- Document Type              ==> (See specific comment)

	- Document Category*     ==> high-level code value (See separate comment)

	- Document Format          ==> Identifier of IG/Profile specifying the type of doc content. Ignore content not supported by requester.

	- Document Mime Type    ==> Distinct from the format (syntax vs semantic)

	- Document Author(s)       ==> (Returned for selection by requester)

	- Document Organization Name and ID ==>That created the document (Returned for selection by requester)

	- Practice Setting (high-level specialty)* ==> High-level Clinical Specialty that generated the doc

SubmissionSet Metadata

	- authorOrg          ==> Organization that authored the submission set

	- source                ==> Person that authored the submission set

	- Submission time ==> Time at which the document is published (made available for sharing/exchange).

All above search parameters shall be required to support server side filtering of matching Document References (shown by ). A subset of these search parameters *shall be supported for search query request (server-side filtering).  All shall be returned by the server whether they were or not included in a query instance.
