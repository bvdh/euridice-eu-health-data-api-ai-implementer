# FHIR-56854: identifier  search parameter

## Description

The CapabilityStatement defines the identifier search parameter for patient identification as SHALL. This may be too restrictive:

	- Not all countries use or expose a single patient identifier

	- In some cases, patient identification relies on a set of demographic attributes (e.g., name, birth date)

	- Cross-border scenarios may require flexibility in identification approaches

Proposed Change:

Revise the requirement level:

identifier: SHALL → SHOULD

Optionally add clarification:

“Where a unique patient identifier is not available, identification MAY be performed using a set of demographic attributes (e.g., name, birth date), in accordance with applicable policies.”

## Resolution

- Status: Resolved - change required
- Resolution: Not Persuasive with Modification
- Resolution Vote: Mattias Colliander / Charles Parisot: 6-0-1
- Vote Date: 2026-08-12

Based on the agreement reached during the HL7 EU API Call on June 10th (see [concept page](https://confluence.hl7.org/x/mlgOGw)) the term “system SHALL support a parameter XY” means a general capability and not that this parameter XY must be present at every query. The wording in the specification will be updated to make this clearer. Therefore, the SHALL requirement to support identifier can remain.

	- MHD describes the minimum floor for query in ITI-67 Narrative, "the consumer SHALL always include a patient reference or Identifier" - which I think is worth preserving.

This means DocumenteReference search has a precondition that the patient has been identified to the Document Consumer, and that the consumer has a patient resource reference, or a patient.Identifier as a result. If the Document Consumer wishes to identify the patient with a set a demographics attributes as you say, it should do so via a Patient$match operation (PDQm).
