# FHIR-56448: Replace GET /Bundle/[id] with DocumentReference.content.url

## Description

The Sequence-Diagram should not include GET /Bundle/[id] in Step 5, because this indicates that FHIR Documents can only be retrieved from an Bundle-Endpoint with a certain [id]. As descriped in [Step 5: Retrieve Document Content](https://hl7.eu/fhir/health-data-api/1.0.0-ballot/en/example-patient-summary.html#step-5-retrieve-document-content) the retrieve-url is defined by DocumentReference.content.url. So DocumentReference.content.url should be used within the Seqence-Diagram instead of GET /Bundle/[id]. This is important because of [Document Location](https://profiles.ihe.net/ITI/MHD/ITI-67.html#236742211-document-location) in distributed scenarios! Not only for XDS/XCA scenarios, where the retrieve-url may look like: [http://example.com/xdsretrieve?uniqueId=urn:uuid:413eb0f7-aa72-4405-86a4-7793a23fcc27&repositoryUniqueId=2.999.756.42.1](https://profiles.ihe.net/ITI/MHD/Bundle-FindDocumentReferences.html), but also where a [MHD Document Responder](https://profiles.ihe.net/ITI/MHD/1331_actors_and_transactions.html#133114-document-responder) within a Document Access Provider supports multiple (distributed) [Resource Idenities](https://build.fhir.org/managing.html) for FHIR Documents. If this will not be supported every Memberstate with a national infrastructure has to implement a centralized [MHDS Document Registry](https://profiles.ihe.net/ITI/MHDS/volume-1.html#150111-document-registry) to serve FHIR documents as single GET /bundle/[id] Source.
