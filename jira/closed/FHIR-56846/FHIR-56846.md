# FHIR-56846: DocumentReference EEHRxF profiles validation

## Description

CapabilityStatement-EEHRxF-DocumentAccessProvider-SubmissionOption.html

The documentation states:

“The server validates the DocumentReference against EEHRxF profiles”

This is potentially misleading:

	- The DocumentReference is (sually) metadata

	- The DocumentReference profiles specified in this guide should not be normative

	- Validation against EEHRxF content profiles applies to the document content itself, not necessarily to the DocumentReference resource

	- The actual validation of the content can only occur after extracting the embedded document from content.attachment.data (or via referenced Binary)

Proposed Change:

Revise the statement to distinguish metadata vs content validation, e.g.:

“The server validates the DocumentReference metadata against applicable profiles. Validation of the clinical document content against EEHRxF profiles is performed on the extracted document (e.g., from content.attachment.data or referenced Binary).”

Make clear that EEHRxF DocumentReference profiles are not normative
