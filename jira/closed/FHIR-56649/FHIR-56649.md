# FHIR-56649: Patient Summary priority area: clarify whether the referenced $summary operation may be used in the example, or is purely informational

## Description

The Patient Summary priority area references operations defined elsewhere (e.g., IPS $summary) with phrasing like "For resource based access, use [link]" or "Note: [other IG] defines an operation". An implementer cannot tell whether the operation is permitted in this IG or merely referenced. The Patient Summary example doesn't show it in use, so an implementer hesitates.

This page defines requirements; if $summary is intended to be permitted, grant that permission explicitly.

Proposed resolution:

Replace informational references with explicit permission: "Servers MAY support Patient/[id]/$summary as the assembly mechanism for the Patient Summary; clients SHOULD discover support via the CapabilityStatement." Coordinate with the on-demand documents change request.
