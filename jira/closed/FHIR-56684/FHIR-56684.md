# FHIR-56684: Legacy and links with the IHE PDQm profile

## Description

The Patient Matching page references the IHE ITI-78 PDQm transaction but only includes a subset of its search parameters. While the identifier parameter is correctly required, other parameters mentioned in the page (family, given, birthdate, _id) are expected to be required as well, but this is not currently the case. Furthermore, additional ITI-78 search parameters are not mentioned: active, telecom, address, address-city, address-country, address-postalcode, address-state, gender, mothersMaidenName. The Patient Matching page states that “Providers MAY support additional PDQm search parameters per ITI-78,” whereas ITI-78 specifies that the Patient Demographics Supplier SHALL be capable of processing all listed parameters. This may lead to a partial implementation of ITI-78.

Proposed resolution :

It would be helpful to clarify whether this restriction is intentional or to better align with the full set of defined search parameters.

## Resolution

- Status: Resolved - change required
- Resolution: Persuasive
- Resolution Vote: Mattias Colliander / Charles Parisot: 6-0-1
- Vote Date: 2026-08-12

The [requirements for search parameters](https://profiles.ihe.net/ITI/PDQm/ITI-78.html#23784121-search-parameters) from the ITI-78 transaction of the IHE PDQm profile will be taken over to the EU Health Data API specification. With one exception: - mothersMaidenName will not be listed, since this Extension is currently not part of the [EU Core Patient](https://hl7.eu/fhir/base/StructureDefinition-patient-eu-core.html)

## Comments

### Reinhard Egelkraut — 2026-06-11

This restriction was not intentional, however, there was an uncertainty was the term “system SHALL support a parameter XY” really means.

Based on the agreement reached during the HL7 EU API Call on June 10th (see [concept page](https://confluence.hl7.org/x/mlgOGw)) the term “system SHALL support a parameter XY” means a general capability and not that this parameter XY must be present at every query.

Therefore, further alignment with the search parameter requirements from PDQm ITI-78 can be achieved.
