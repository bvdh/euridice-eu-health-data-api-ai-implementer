# FHIR-56711: Revise  DocumentReference.date cardinality

## Description

Issue:

The profile constrains DocumentReference.date in a way that may be misleading. This element represents the indexing/registration timestamp of the DocumentReference, not the clinical document date itself.

Constraining it (e.g., making it mandatory) may:

	- - Create confusion with the actual document creation/effective date

 - Lead to incorrect population of metadata

 - Conflict with cases where this metadata is not available or not relevant

Proposed Change:

Set DocumentReference.date cardinality to 0..1, and clarify its meaning, e.g.:

“DocumentReference.date represents the metadata creation/indexing timestamp, not the clinical document date.”

Optionally:

	- - Reference the correct element for document timing (e.g., content.attachment.creation or document-specific fields)
