# FHIR-56703: Specification should include more API specific implementation guidance

## Description

In the Health Access API we tried to set a common set of actors that can mapped to each situation/instantiation of EHR systems in Europe. This has been chosen based on the assumption that there is a large commonality between these deployments.

I agree that this is the case, but I fear that in doing so we have lost a large part our audience that require more guidance on what is required in what deployment.

Furthermore, as we did not explicitly label these API’s and the requirements, it is hard to test to what requirements each API can be held. This also resulted in the, in my eyes, focus on national infrastructures. This led to uncertainties related to what does this mean for other deployments such as the Wellness API, Patient Access API and inner-healthcare-provider API.

So, based on the feedback and discussions I suggest that we start the spec in the with a chapter similar to an IHE Volume 1 section that:

	- Start with describing the different API’s that occur with the EU infrastructure (e.g. using the original picture) and their variation (resource vs document)

	- List and agree on the EHDS (and other) requirements related to these APIs

	- Indicate what part of the specifications are used to satisfy these requirements

It is my expectation that this work will clarify blind spots (e.g. import, patient API specific stuff, ...) and focus discussions on the specific contexts and thereby prevent a topic in context bleeding over in another.
