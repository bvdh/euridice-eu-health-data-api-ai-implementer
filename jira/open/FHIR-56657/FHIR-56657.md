# FHIR-56657: Actor grouping concept used incorrectly: the IG mixes "grouped" (IHE: all transactions supported) and "internalized transactions" (different concept) — introduce a combined actor

## Description

This IG presents actor grouping in two incompatible ways.

The first appears in actors.html#document-exchange, where the constituent IHE actors and their inherited transactions are listed as a grouping — consistent with the IHE convention (per [IHE TF Volume 1 §3.1.1](https://profiles.ihe.net/ITI/TF/Volume1/ch-3.html)) that a grouped actor implements all of the required transactions and content modules of the constituent actors. The same convention is shown visually in this IG's Figure: Document Exchange - Actor Groupings.

The second appears in the same actors.html page, in the Document Publisher description:

Can be grouped with Access Provider, in which case the publishing transactions are internalized.

This contradicts the IHE definition of grouping by implying that some required transactions for one or both actors need not be supported. IHE handles transaction internalization by defining a separate combined actor — a distinct actor in its own right, not a grouping.

Proposed resolution:

Update the actors page (and references on document-exchange.html#overview and index.html#approach):

_ Document Publisher (client) — Produces EEHRxF FHIR Documents, publishes them to a Document Access Provider. Can be combined with Access Provider, in which case publishing transactions are internalized. _(change "grouped" → "combined")*

	- Document Access Provider (server) — Provides access to EEHRxF FHIR Documents via query APIs to Document Consumers. See Document Submission Option below for systems not combined with a Document Publisher; the option lets such systems accept publication from external producers.

	- Add a sequence diagram for document exchange transactions with the combined publisher/access provider actor and the document consumer actor (alongside the existing three-actor diagram).

	- Add Example 2 — Combined Producer/Access Provider — a single combined Document Publisher / Access Provider actor.

	- Add Example 2B — Combined Producer/Access Provider + Resource Access — a combined Document Publisher / Access Provider grouped with a Resource Access Provider.

This aligns the IG with IHE actor-grouping conventions and removes ambiguity about which transactions an internalized-transaction system must implement.
