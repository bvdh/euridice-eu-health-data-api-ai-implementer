# FHIR-56691: Strengthening Capability Discovery

## Description

A rather rich content is proposed in the capability statement discovery:

“The server returns a CapabilityStatement resource that declares:

	- Supported FHIR version

	- Supported resource types and profiles

	- Supported interactions (read, search, create, etc.)

	- Supported search parameters

	- Actor conformance and priority category support (see below)”

This list is confusing as it does not match the rest of the specification that states: Consumer inspects:

	- instantiates (actor conformance)

	- implementationGuide (content IGs)

	- rest.resource.supportedProfile (profiles)

	- rest.resource (supported resources)

The example that follows is quite clear but inconsistent with introduction list.

The textual comments in Section 3.1.3, 3.1.4 and 3.15 make the analysis of the capability statement quite clear and avoids creating some inconsistent interpretations.  Such language should be normative, as it would avoid such situations by making unexpected interpretations.

Proposed resolution :

Make the interpretation logic of the capability statement in Section 3.1.3, 3.1.4 and 3.15 as normative language to avoid creating some inconsistent interpretations of the capability statement.
