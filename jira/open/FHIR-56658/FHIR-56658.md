# FHIR-56658: Don't EU-lock value sets — prefer universal-realm or LOINC where the underlying capability has utility outside the EU

## Description

This IG's work to operationalize EHDS interop via FHIR will establish precedent not just in the EU but likely across FHIR clinical interop globally — between care settings and between nations. The IG should strive not to unnecessarily limit software compliant with it to EU-only use.

For example: don't mandate use of a priority-category-specific value set such as ehds-discharge-summary when a universal-realm category value set or LOINC's 34105-7 would better serve global health IT interop. Similarly, per open-issues.html#issue-5-capabilitystatement-and-priority-category-declaration, don't mandate a conformance statement that only makes sense in the EU when the same functionality (a queryable patient summary) could be valuable outside an EU context. At an absolute minimum, don't restrict a document of type …CodeSystem/eehrxf-document-priority-category-cs from also being a …CodeSystem/cafex-document-priority-category-cs or similar — co-existence on the same DocumentReference.type or Composition.type should be permitted.
