# FHIR-56584: Authorization & User Level

## Description

Chapter 3.2.2 and 3.2.9 declare that user-level authentication/authorization are not in scope of this IG (but MAY be in a future version).

Isn't user level information in a token and user-level authentication also a basis for Audit Message information and therefore a rather important part of the specification?

### JoshPriebe — 2026-05-19

What's in the regulation for user-level logging?

	- [Annex II (3)](https://eur-lex.europa.eu/legal-content/EN/TXT/HTML/?uri=OJ:L_202500327#anx_II)- EHR Logging Component must log user access for every group of access events.

	- [Article 9](https://eur-lex.europa.eu/legal-content/EN/TXT/HTML/?uri=OJ:L_202500327#art_9)- Patient has the right to obtain access logs for access events of the health professional access service (through the patient access service)

Do EHR systems need to interoperate their access logs, for example to send to the patient health data access service?

	- No requirement on EHR systems to interoperate those logs is included in the Annex.

	- The patient's right to obtain logs (Article 9) is clearly scoped to health professional access service access events, not to all EHR system access events.

So it is not clearly in regulatory scope do transmit user access data. Xt-EHR has come to the same conclusion in Deliverable 5.1.

Do the logging component requirements include end-user access events (e.g. end user in the UI) or API access events, or both?

	- It seems to me to suggest end-user access events ("designed to enable access by individuals"); but it's a bit ambiguous.

	- Consider an example cross-EHR API access scenario; EHR A releases data to EHR B via API; EHR B may have a user in the loop initiating this request, but afterwards EHR B may store the data and show it to other users. EHR A cannot log all of the user access events that happened in EHR B because it does not know who has accessed the data in EHR B. EHR B will have it's own logging component requirements, and log each user access as the data is shown.

Because of this; the way the Xt-EHR group decided to handle this in D5.1 is by separating responsibilities and enabling a chain of access events to be constructed:

*EHR A releases data via API to EHR B (EHR A logs release of data to EHR B at a system level - in fact what is happening).

*EHR B shows this data to this data to end-user(s) (EHR B logs each user access event as required by the logging component).

This credibly allows a chain of access events to be constructed by correlating logs, and places responsibility where it can be reasonably actioned (each EHR is in charge of logging access by its users)

[Egelkraut](https://jira.hl7.org/secure/ViewProfile.jspa?name=Egelkraut) where does your understanding differ here? It's clear the health professional access service is required to log user-level events; but we do not intend specify the complete requirements for access services here (just the Interop Component API interactions). Or would you just request that this scenario and position should be well-described in this IG?

The European logging software component of an EHR system designed to enable access by healthcare providers or other individuals to personal electronic health data shall provide sufficient logging mechanisms that record at least the following information on every access event or group of events ...
