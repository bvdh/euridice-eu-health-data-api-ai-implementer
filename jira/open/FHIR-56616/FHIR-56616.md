# FHIR-56616: Revise the IUA Authorization Client actor

## Description

The guide appears to introduce additional requirements for the actor labeled as an IUA Authorization Client. It is unclear whether an actor that includes such additional constraints can still be considered compliant with the standard definition of an IUA Authorization Client.

 

If additional requirements are imposed beyond the standard IUA Authorization Client definition, a distinct actor SHALL be defined to avoid ambiguity and ensure conformance clarity

## Resolution

- Status: Triaged
- Resolution: Persuasive with Modification

Removed the IG-authored CORS requirements from the spec thereby removing specific IUA requirements. Retained the protocol-neutral Health Data API Authorization Client separately from the IHE IUA Authorization Client and SMART roles. Kept the MHD transaction-scope guidance conditional on supported ITI-65 through ITI-68 transactions whose MHD actors are grouped with IUA; this integration-specific scope guidance does not by itself redefine the IHE IUA Authorization Client.
