# FHIR-56696: Document Exchange needs an explicit support for submission sets and life cycle management

## Description

Document Exchange needs an explicit support for submission sets and life cycle management

The support of MHD as proposed makes sense, however:

	- The document search proposed in the use of the MHD Document Reference resource is too primitive as it only relies on two mandatory parameters: documentType limited to the EHDS Data Category (encoded by a value set of 6 arbitrarily picked LOINC Code) and document contentType (MIME Type).

	- There are critical search parameters that are missing and are associated with the submission of the document rather than the document creation, nor the time when the care delivered is recorded by the document. These are:

 - Document publishing time. This ensures that incremental queries can be performed (querying for any documents published after time hh:mm:ss, when this time is the time of the last query).

 - LastUpdated The attribute «lastUpdated» allows to easily search for modified documents since a point in time.

 - authorOrg. Organization that authored the submission set.

 - source. Person that authored the set of documents submitted.

	- The shared/published document has a life cycle in that such a document can be updated and replaced by an updated version of the document. This needs to be discussed the EU Health Data API, as it is real world.

 

Proposed resolution :

	- It is proposed to require critical search parameters that are missing and are associated with the submission of the document. These are:

 - Document publishing time. This ensures that incremental queries can be performed (querying for any documents published after time hh:mm:ss, when this time is the time of the last query).

 - LastUpdated The attribute «lastUpdated» allows to easily search for modified documents since a point in time.

 - authorOrg. Organization that authored the submission set.

 - source. Person that authored the set of documents submitted.

	- The definition of the ITI-105 Simplified Publish transaction provided in the implementation guide appears to be incomplete compared to the one provided by the MHD profile. In theory, after receiving this transaction, the Document Access Provider should generate a Submission Set associated with the received Document Reference (see MHD 2:3.105.4.1.3). However, this aspect of generating a Submission Set is not addressed in the implementation guide. This appears particularly necessary given that some priority categories define their own Document Reference structures. Information on how to create Submission Sets from specific Document References is therefore required.

	- The implementation guide addresses the process for publishing new health documents via transaction ITI-105 Simplified Publish (and now adding the Option ITI-65). However, it does not mention the mechanisms for managing the lifecycle of these health documents. Some guidance on how to update or unpublish these documents appears to be necessary.
