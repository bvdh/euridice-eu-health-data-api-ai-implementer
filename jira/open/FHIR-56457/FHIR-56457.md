# FHIR-56457: API are also defined in the Articles

## Description

In paragraph 1.1 "Regulatory Basis" ([Home - EU Health Data API v1.0.0-ballot](https://hl7.eu/fhir/health-data-api/1.0.0-ballot/en/index.html))

ANNEX II of the EHDS regulation is not the only source of requirements for the Interoperability Component of EHR systems. For exemple, according to Article 5, an EHR system which implements an health data access service (HDAS) through an API should be capable to import health data in the EHR of a natural person. And an EHR system used by a natural person could provide an API to send data to their EHR. I suggest adding a line:

	- Article 5: "Natural persons [...] shall have the right to insert information in the EHR of those natural persons through electronic health data access services or applications [EHR systems] linked to those services [...].

Please also have in mind that the regulation brings obligations for manufacturers, but also for Member States and Healthcare Providers:

	- Obligations for Member States to provide Health Data Access Services (for natural persons) and health professional access services (for health professionals). HDAS and HPAS can be web portals, APIs, secure messaging systems ... This IG focus on APIs.

	- Obligations for healthcare providers to transmit or to give access to health data (portablity).

	- Obligations to go through MyHealth@EU (eHDSI) to exchange data cross-border.

Some Members already deployed an infrastructure for sharing health data and they will rely on their existing infrastructure to implement the EHDS regulation. During the CapacityHD sessions "Preparing for the EEHRxF (Interoperability and Interoperability Testing) continued: Towards an EHDS Use Cases Catalogue for Primary Use" hold in Athens and Brussels, the participants (only Member States) defined some of the use cases of the regulation based on the Articles 3, 4, 5, 7, 11, 12, 23 and 48. Then they designed some workflows based on the HDAS, HPAS and eHDSI components. New transactions were defined like sending health data to central/regional EHR systems which will consolidate the data. The IG should also address the transactions between these "mandatory" services and EHR systems, the "hidden" transactions which will make the regulation work and of course the "basic" transation defined in ANNEX II. If not, this IG will not be very helpfull, each MS will write its own IG, and interoperability in Europe will be a failure.
