# FHIR-56692: Document Exchange – Adding ITI-65 as a publishing option

## Description

Document Exchange – Adding ITI-65 as a publishing option

The support of MHD as proposed makes sense, however, the use of ITI-105 for the publication has significant downside compared to ITI-65 with comprehensive metadata:

	- It is important to avoid as much as possible that the Document Access Provider actor be forced to open the document content (beyond the generic document reference resource) to access the content to populate its search metadata.

	- The document publisher actor is the system that shall be responsible for the accuracy of such metadata.

	- There is a need to track the author of the submission of a document.The Submitter is legally responsible and needs to be recorded. The submitter is often different from the clinical author or authenticator of the document.  This is accomplished in MHD using the submission set which is not supported by the ITI-105 transaction, but by an ITI-65 transaction.

	- When multiple documents need to be submitted in an atomic way (for example a hospital submit a discharge report along with a lab report related to the same hospital visit. It is important that both documents be submitted or none be submitted if one submission fails.  An ITI-65 submission set supports this atomic operation.

 ** Proposed resolution :

It is proposed to support two submission options: 

	- A basic submission based on ITI-105

	- A robust submission based on ITI-65 (to have the atomicity, submission responsibility and other benefits listed above).

The addition of this ITI-65 transaction must be combined with a set of definitions to determine its scope (what type of resource can be published via an ITI-65, is iterative resource submission permitted, etc.).

For both publish transactions the same search metadata needs to be included and aligned on the Uncontained Comprehensive Metadata specifications of MHD (See companion issue resolution).
