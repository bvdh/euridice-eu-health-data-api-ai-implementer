# FHIR-56475: Use cases

## Description

In paragraph 4.0.2 "Use Case Examples" ([Implementation - EU Health Data API v1.0.0-ballot](https://hl7.eu/fhir/health-data-api/1.0.0-ballot/en/implementation.html)), the use cases are not enough business oriented. During the CapacityHD sessions "Preparing for the EEHRxF (Interoperability and Interoperability Testing) continued: Towards an EHDS Use Cases Catalogue for Primary Use" hold in Athens and Brussels, the participants (all from Member States) worked on real-world use cases based on Articles 3, 5 7, 11 and 48. For example:

AHD_NP_HDAS - A Natural Person (NP) visited a radiology clinic for an X-ray of their right knee. The radiology report is stored in a repository (EHR system) which is accessible through a HDA Service provided trhough an API. The radiology clinic is located in the country of affiliation of the NP. The NP wants to access their health data.

PORT_HP_HPAS - During a business trop, a NP experiences stomach pain and goes to the emergency department of a hospital in that country. A few weeks later, the NP consults their family doctor in their country of affiliation. The family doctor wants to access the health data of the NP which were acquired abroad.

For each use cases, the participants worked on the implementation of the use cases based on the central components of the regulation: HDA Services (Article 4), HPA Services (Article 12) and eHDS Infrastructure (Article 23). Services can be a web portal, an API, a messaging system. Countries are free to choose the implementation of these services. For exemple:

AHD_NP_HDAS_2 - The NP uses a mobile application (or any other patient application) provided by a manufacturer to access their health data stored in their Electronic Health Record (EHR). The patient application uses an API of the HDA Services.

[https://fichiers.numerique.gouv.fr/explorer/items/files/06a74818-bdd6-40ed-b44d-93bb9d3d9f26](https://fichiers.numerique.gouv.fr/explorer/items/files/06a74818-bdd6-40ed-b44d-93bb9d3d9f26)

PORT_HP_HPAS-7 - The country of treatment does not provide a HPA service to access health data of foreigner. There are different solution for solving the use case. For exemple, the healthcare organisation uses a HPA API connected to the eHDS Infrastructure for pushing the health data to the EHR of the patient in their country of affiliation.

[https://fichiers.numerique.gouv.fr/explorer/items/files/19340839-04fa-47fa-8ea9-677c81254972](https://fichiers.numerique.gouv.fr/explorer/items/files/19340839-04fa-47fa-8ea9-677c81254972)

These 2 implementations demonstrates that:

	- AHD_NP_HDAS_2 - Article 3.1 does not specify the HDA Service when it is provided as an API. Since this API is implemented through on to several EHR system(s), it must be conform to the EEHRx Format (ANNEX II 2.1). Since the HDA API returns the health data in the format, the patient application does not have to reformat the data for downloading. The workload is on the HDA API. The HDA API is a "Document Acces Provider" and the patient application a "Document Consumer". Good match!

	- PORT_HP_HPAS-7 - Article 7.2 does specify that the health data must be transmitted in the EEHRx Format when the healthcare provider is located in a different country. If the country provides a HPA API connected to the eHDS Infrastructure, this API must be then conform to the EEHRx Format. In this implementation, the business application used by the healthcare provider is a "Document Publisher". The HPA API of country B is a "Document Acces Provider". It communicates wuth the HPA API of country A. But a transaction is missing to send the health data to the EHR system which will receive the data. The "notify push" is maybe a solution that will be implemented in some countries like Netherland but not all country in Europe.

All the work done during the 2 capacityHD session will be consolidated in a new eHealth Network Task Force. Euridice and this TF will have to synchronize.
