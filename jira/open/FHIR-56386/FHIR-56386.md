# FHIR-56386: Health Professional Access Service Authorization

## Description

In 4.2.4 Technical Flow the Authorization part just mentions SMART as a requirement.

The request of this ticket is to add IHE IUA as well since it is the basis of the Authorization described in the EU Health Data API specification.

## Resolution

- Status: Triaged
- Resolution: Persuasive

See [PR #99 — Eu health data api ballot recon authorization](#99 — Eu health data api ballot recon authorization)([https://github.com/euridice-org/eu-health-data-api/pull/99)](https://github.com/euridice-org/eu-health-data-api/pull/99)) This ticket is addressed by supporting both SMART and IHE IUA, with the applicable protocol selected according to the environment where the EHR system is deployed and the specific EHR-facing API boundary. The current implementation branch describes SMART App Launch for applicable interactive Healthcare Provider flows, SMART Backend Services for qualifying pre-authorized server-to-server flows, and IHE IUA roles for qualifying National Interoperability Infrastructure endpoints. This environment-specific approach does not require IUA in every deployment or require SMART and IUA together on one endpoint. The clarification is present in the current local source at [commit `1638e75`]([https://github.com/euridice-org/eu-health-data-api/commit/1638e75b81a8c43126ab44eb2f3bba92b15190b2](https://github.com/euridice-org/eu-health-data-api/commit/1638e75b81a8c43126ab44eb2f3bba92b15190b2)).
