# FHIR-56660: Health Data Access Service page describes only the broker model; should also reference the deployed direct-EHR-auth pattern (SMART/IPA)

## Description

The Health Data Access Service page describes only the broker model:

Patient authenticates to the Health Data Access Service (out of scope for this IG) / Service authenticates to Provider systems using backend services credentials.

The page should also reference the deployed and simpler method for patients to access clinical data — authenticating directly to the EHR (often with pre-existing portal credentials) as defined in IPA and SMART on FHIR. Member-state and architectural considerations may favor the broker model, but direct-EHR-auth is the model in production today. Provider systems typically enforce patient consent preferences by not using system-to-system authorization — another reason direct-EHR-auth deserves explicit acknowledgement.

Proposed resolution:

Add a paragraph on the Health Data Access Service page (and the Health Professional Access Service page where applicable) acknowledging direct-EHR-auth as a deployed alternative, with a brief note on consent-enforcement implications. Don't replace the broker model — both are valid and reflect different MS architectures. The goal is acknowledgement, not preference.
