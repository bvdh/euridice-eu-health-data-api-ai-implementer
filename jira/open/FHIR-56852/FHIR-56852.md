# FHIR-56852: Systems SHOULD support SMART Backend Services

## Description

The statement:

“Systems SHALL support SMART Backend Services authorization for all transactions.”

is too restrictive and conflicts with the need for flexibility in authorization mechanisms within the EU context. As noted elsewhere in the guide, SMART is a preferred approach but not the only possible one.

Proposed Change:

Revise the requirement level, e.g.:

“Systems SHOULD support SMART Backend Services authorization for all transactions.”

Optionally add:

“Other authorization mechanisms MAY be used, provided they comply with applicable EU regulations and trust frameworks.”

## Resolution

- Status: Triaged
- Resolution: Persuasive with Modification

This ticket is addressed by the authorization approach in [euridice-org/eu-health-data-api#99 — Eu health data api ballot recon authorization](#99 — Eu health data api ballot recon authorization)([https://github.com/euridice-org/eu-health-data-api/pull/99](https://github.com/euridice-org/eu-health-data-api/pull/99)). The IG requires authorization for all transactions and specifies SMART or IHE IUA, as selected for the environment and use case, with the applicable flow. SMART Backend Services applies to pre-authorized system-to-system use; it is not required for every transaction. Requirements of the selected authorization specification remain applicable. This addresses the concern with the blanket SMART Backend Services requirement without adding unrestricted authorization mechanisms.
