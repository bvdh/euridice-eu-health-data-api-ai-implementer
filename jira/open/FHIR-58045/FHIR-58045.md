# FHIR-58045: CapabilityStatement for Access Provider: Relax Support for Patient

## Description

During the discussion for patient lookup a conclusion was reached that not every access provider system has to provide a Patient Lookup API, it depends on the national/regional/local architectures which components have to provide it or if it is needed at all.

A circumstance that was also reported via a ballot ticket see [FHIR-56155](https://jira.hl7.org/browse/FHIR-56155).

This leads to a problem with the current version of the following CapabilityStatements:

	- CapabilityStatement: EEHRxF Document Access Provider

[EEHRxF Document Access Provider CapabilityStatement - EU Health Data API v1.0.0-ballot](https://build.fhir.org/ig/euridice-org/eu-health-data-api/en/CapabilityStatement-document-access-provider-eu-api.html)

	- CapabilityStatement: EEHRxF Grouped Document Publisher/Access Provider

[EEHRxF Grouped Document Publisher/Access Provider CapabilityStatement - EU Health Data API v1.0.0-ballot](https://build.fhir.org/ig/euridice-org/eu-health-data-api/en/CapabilityStatement-document-publisher-access-provider-eu-api.html)

There are two issues:

	- The Patient Resource listed as SHALL -> based on the conclusion above it should be a SHOULD

	- and ITI-78 Patient Demographics Query is listed a R instead of O
